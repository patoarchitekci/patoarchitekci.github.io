  ### 🎙️ Odcinek #209: GitHub Universe 2026
  
  GitHub ogłasza, że „SDLC is no longer a linear path”. Zamiast znanej pętli planowania, budowania, weryfikacji, wdrażania i obserwacji pokazuje układ z wiedzą i kontekstem w centrum. Na każdym etapie pojawia się człowiek, agent i zestaw artefaktów.
  
  Łukasz streszcza tę wizję bez marketingowej warstwy: **„Czytajcie, nie Agile Manifesto, tylko Scrum. Chcemy zrobić nowego Scruma.”**
  
  **Kluczowe wątki:**
  
  #### ⭐ Agentowe SDLC i miejsce dla człowieka
  
  GitHub chce przestać być wyłącznie platformą do przechowywania kodu i uruchamiania CI/CD. Nowa opowieść obejmuje cały agentowy cykl wytwarzania oprogramowania.
  
  Jednocześnie firma uspokaja developerów hasłem „More room for human judgment”. Szymon widzi w tym dwa komunikaty: GitHub chce obsługiwać cały proces, ale nie chce wystraszyć ludzi wizją ich całkowitego usunięcia.
  
  Łukasz sprowadza problem wymagań do jednego zdania: **„Czyli nie mamy wymagań, jak zawsze, ale pojawia się agent, który nam pomoże nie mieć wymagań dalej.”**
  
  #### 📈 110 milionów pull requestów od agentów
  
  Skala GitHuba nadal robi wrażenie: 225 milionów programistów, 18 miliardów commitów i dodatkowe 50 TB/s przepustowości sieciowej.
  
  Najmocniejsza liczba dotyczy jednak agentów AI. We wrześniu otworzyły 110 milionów pull requestów - sześć razy więcej niż w marcu tego samego roku. Łukasz przypomina, że przy takim tempie wzrostu problemy ze stabilnością trzeba oceniać w kontekście realnego obciążenia platformy.
  
  #### 🤖 Copilot sam wybierze strategię
  
  Copilot Fusion, wcześniej znany jako Hydra, ma trzy tryby: Single, Cascade i Critic. Jego zadaniem jest dobranie najtańszej strategii rozwiązania promptu.
  
  Zamiast uruchamiać drogi model do każdego zadania, system może wykorzystać jeden model do planowania, a inny do implementacji. Szymon podsumowuje potrzebę automatyzacji wyboru jasno: **„Ta opcja decyzji musi odejść od developera.”**
  
  Mniej przekonująco wypada Copilot podpięty do GitHub Projects. Szymon widzi sens głównie wtedy, gdy Projects staną się kolejką pracy dla wielu agentów. Sam interfejs ocenia krócej: **„To wygląda jak ubogie Trello.”**
  
  #### 🔐 Security jest najmocniejszą częścią ogłoszeń
  
  Package firewall ma chronić przed wciąganiem niebezpiecznych zależności, choć na razie działa tylko dla npm. License Compliance pozwala blokować pakiety z licencjami niezgodnymi z zasadami organizacji.
  
  Najciekawiej wygląda Dependabot reachability. Nie kończy analizy na informacji, że używany pakiet zawiera podatność. Sprawdza, czy kod rzeczywiście wywołuje podatną funkcję. Obecnie funkcja obejmuje JavaScript i TypeScript.
  
  Jak tłumaczy Szymon: **„Czyli przejście z tego, że co z tego, że pakiet ma podatność, powiedzenie czy Wy używacie tej podatności.”**
  
  #### 🧠 Pamięć, dreaming i automatyzacje
  
  Copilot Memory osiągnął GA. W preview pojawił się dreaming, czyli analiza zakończonych sesji i dopisywanie wniosków do pamięci, instrukcji oraz skilli w repozytorium.
  
  Copilot Automations dostał triggery, łączenie automatyzacji, integracje MCP, kontrolę kosztów i możliwość uruchamiania w modelu self-hosted. To nie są funkcje projektowane dla małych repozytoriów. Są elementem platformy dla dużych organizacji.
  
  #### 🏢 Kierunek pozostaje ten sam: Enterprise
  
  Nowa architektura Gita rozdziela compute od storage'u. Część GitHub Actions klientów Enterprise będzie mogła działać także na AWS. Funkcje Copilota można rozliczać przez AI Credits bez osobnej subskrypcji, ale również tylko w Enterprise.
  
  Łukasz podsumowuje strategię GitHuba bez niedomówień: **„Kierunek się nie zmienił, że ciągle jest jeden. Czyli walimy w Enterprise.”**
  
  Na koniec zostaje GitHub Spark. Projekt został wyłączony 31 sierpnia, bez większego komunikatu. Jak zauważa Szymon: **„Bo nie było o tym żadnej informacji.”**
